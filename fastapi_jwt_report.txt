FastAPI + JWT Authentication Quick Guide

1. What this app does
This project is a small FastAPI API that connects to PostgreSQL, stores users, hashes passwords, and uses JWT tokens to protect routes.

2. Main files
- database.py: creates the PostgreSQL connection, session factory, and SQLAlchemy base class.
- models.py: defines the Users table.
- auth.py: handles user creation, login, password hashing, token creation, and token verification.
- main.py: creates the FastAPI app, registers routers, and exposes the protected home route.

3. FastAPI concepts used here
- FastAPI app: the main application object that receives requests.
- Router: a grouped set of endpoints, used here for /auth.
- Dependency injection: FastAPI can automatically provide objects like a database session or the current user.
- Response models: Pydantic models describe the shape of returned data.

4. Database flow
- database.py creates an engine that points to PostgreSQL.
- SessionLocal creates a new DB session for each request.
- models.py maps Python classes to database tables.
- main.py calls Base.metadata.create_all(bind=engine) so SQLAlchemy can create tables if they do not exist.

5. User registration flow
- The client sends username and password to POST /auth/.
- FastAPI validates the JSON body with CreateUserRequest.
- bcrypt hashes the password before storing it.
- A Users row is inserted into the database.

Why hash passwords?
- Never store plain text passwords.
- A hash is one-way, so the original password is not saved.

6. Login and JWT flow
- The client sends form data to POST /auth/token.
- authenticate_user checks the username in the database.
- bcrypt.verify compares the submitted password with the stored hash.
- If valid, create_access_token builds a JWT.
- The token contains claims such as sub (username), id (user id), and exp (expiration).

7. How JWT protects routes
- oauth2_bearer reads the Bearer token from the Authorization header.
- get_current_user decodes the token using SECRET_KEY and ALGORITHM.
- If the token is valid, the route receives the user data.
- If the token is missing or invalid, FastAPI returns 401 Unauthorized.

8. Protected endpoint example
- The / route in main.py depends on get_current_user.
- That means the request must include a valid JWT token.
- Without a token, the route rejects the request.

9. Important notes
- bcrypt has a 72-byte password limit.
- The app currently blocks longer passwords before hashing.
- The tokenUrl in OAuth2PasswordBearer points to /auth/token, which is the login endpoint used by Swagger UI.
- There is a small bug in get_current_user in auth.py where the decoded payload is assigned incorrectly; if token decoding misbehaves, that is the first place to inspect.

10. Mental model
Request -> FastAPI route -> dependency injection -> database/session or token check -> business logic -> response

For authentication:
Register -> hash password -> store user
Login -> verify password -> issue JWT
Protected route -> read JWT -> decode -> allow or deny access
